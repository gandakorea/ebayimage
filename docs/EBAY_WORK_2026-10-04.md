# 10월4일 이베이 작업

2026-10-04(한국 시간)의 작업 결과와 앞으로 재사용할 실행 규칙이다. 사진의 시각 규격은 [작업규칙.md](../작업규칙.md), 등록 필드는 [등록 규칙](LISTING_RULES.md), 계정 순서는 [계정 분리 규칙](EBAY_ACCOUNTS.md)을 따른다.

## 사용자 승인과 작업 순서

- 사진 편집 도구/API 사용은 상시 승인되었다. 기존 판매자 워터마크를 깨끗하게 제거하고 제품 형상·각인·라벨·단자·홀로그램을 원본과 대조한다. 음성 및 사진 외 추가 유료 API 금지는 유지한다.
- 사진을 먼저 완성한 뒤 필요한 비밀값 사용과 기존 eBay/Vercel 연결 설정을 진행한다. 같은 승인 범위는 반복 확인하지 않는다. 서비스가 요구하는 로그인·본인 인증이나 도구의 강제 승인까지 생략할 수 있다는 뜻은 아니다.
- 미국 `gandakorea / EBAY_US / USD` 배치 전체를 등록하고 공개 검수한 뒤 호주 `sihooshop / EBAY_AU / AUD`를 진행한다. 각 계정의 실제 인증 판매자를 확인하고 인증·정책·SKU·등록 기록을 분리한다.
- 오늘 워터펌프의 기존 등록을 발견했으나 사용자가 **오늘 작업표대로 새 상품 추가 등록**을 지시했다. 기존 상품은 유지했다. 이 결정은 오늘 작업표의 범위이며 모든 미래 중복 등록에 대한 일반 허용으로 확대하지 않는다.

## 사진 준비와 검수

1. 새 배치 전에 사진 규칙과 워크플로를 읽고 편집 내용을 사용자에게 알린다.
2. 원본을 보존하고 품번별 최종 PNG를 `완성본/<품번>/`에 저장한다. 대표사진은 `<품번>.png`, 이후 `_1.png`, `_2.png` 순서다.
3. 1000×1000 PNG, 흰 배경, 규정된 `KOREA AUTOPARTS` 워터마크를 확인한다. 기존 워터마크 제거 중 손상된 제품 표기는 원본 픽셀과 대조·복원한다. 생성된 복원을 숨은 구조나 장착 정보의 증거로 삼지 않는다.
4. 비공개 Blob에는 검수 완료된 사진만 저장한다. 공개 등록 후 API의 사진 URL·장수·순서를 재조회하고 공개 갤러리도 확인한다. 가능한 경우 공개 사진을 로컬 완성본과 픽셀 비교한다.

## 등록 요청과 저장소 실행 규칙

- 미국 자동차 부품 Trading 등록은 `Site=eBayMotors`, `X-EBAY-API-SITEID=100`을 함께 사용한다. 판매자 인증의 등록 마켓은 `EBAY_US`다. `Country=KR`와 확인된 상품 위치를 명시한다.
- 실제 공개 등록 전에 `VerifyAddFixedPriceItem`으로 사전 검증한다. 검증 결과를 공개 등록 완료 기록으로 저장하지 않는다.
- 호환표 추출 시 Name/Value가 없는 노드를 제외한다. 빈 값이나 null이 XML 생성 단계에 전달되지 않도록 확인한다.
- 호주 REST 요청에는 `Content-Language`와 `Accept-Language`를 명시적으로 `en-AU`로 설정한다.
- 신규 SKU의 offer 조회에서 `404 / errorId 25713`은 기존 offer 없음으로 처리하고 새 offer를 만든다. 다른 오류는 정상 상태로 숨기지 않는다. 재시도는 같은 SKU와 실행 기록을 사용해 중복 생성을 방지한다.
- 변경 가능한 Blob 작업표·등록 패키지·실행 기록은 `useCache:false`로 최신 원본을 읽는다. 오래된 캐시로 준비 상태나 등록 번호를 덮어쓰지 않는다.
- 즉시 실행도 준비된 미국 배치를 먼저 처리하며, 작업표의 모든 유효 상품이 미국 등록을 완료하기 전에는 호주 실행을 시작하지 않는다. 오늘은 US 전용 실행 후 사람이 공개/API 검수를 마친 다음 AU를 실행했다.
- 비밀값은 비공개 환경 파일과 서버 환경변수로 관리하고 Git·채팅·로그에 노출하지 않는다. 로컬 파일 권한은 0600을 사용한다. 필요한 상품·카탈로그 조회는 서버 인증을 사용하는 보호된 읽기 API로 수행한다.
